These are excluded because they are regenerable, machine-specific, or **non-redistributable
challenge data** (`RULES.md` §2.2). The local workspace can be deleted safely once the items
below are either regenerated or restored from their source.

| Excluded path | Typical size | Why | How to restore |
|---|---|---|---|
| `DATA/**/*.tsv`, `DATA/**/*.zip` | ~3.4 GB | Non-redistributable challenge data | Re-download the official `student_resource.zip`, extract to `DATA/student_resource/` |
| `kaggle/staging/` | ~3.4 GB | Duplicate raw data + Linux wheels/deps produced by pushes | Regenerated by `python kaggle\push_all.py …` / `kaggle\auto.py` |
| `submission/staging/` | ~300 MB | Build staging for the zip | Recreated by `submission/make_zip.py` |
| `.venv/` | ~335 MB | Machine-specific environment | `uv venv .venv --python 3.12` + `requirements.txt` |
| `artifacts/` | ~3 MB | Pipeline caches; parquet embeds cleaned raw records | Re-run the pipeline stages |
| `__pycache__/`, `.pytest_cache/`, `graphify-out/cache/`, `tools/eda_cache/` | small | Caches | Regenerated automatically |
| `DATA/__MACOSX/` | small | macOS archive junk | n/a |

> If `DATA/` is ever needed again and the original download is unavailable, the 7 TSVs are

## 4. Git LFS

Large files are stored with [Git LFS](https://git-lfs.com/). Patterns in [`.gitattributes`](../.gitattributes):

```
*.tsv      filter=lfs diff=lfs merge=lfs -text
*.zip      filter=lfs diff=lfs merge=lfs -text
*.parquet  filter=lfs diff=lfs merge=lfs -text
*.png      filter=lfs diff=lfs merge=lfs -text
```

**On a fresh clone** (on any machine):

```powershell
git lfs install     # once per machine
git lfs pull        # download the actual file contents
```

Without LFS the LFS-tracked files appear as small text pointers.

**Adding new large files:**

```powershell
git lfs track "path/or/glob"     # updates .gitattributes
git add .gitattributes path/or/glob
```

**Quota note.** GitHub's free tier includes ~1 GB of LFS storage and ~1 GB/month of LFS
bandwidth. This repository's LFS content is roughly **0.75 GB** (`output/` ~640 MB +
`team_submission.zip` ~124 MB), which fits but is close to the limit. Cloning/fetching LFS
content counts against bandwidth; if you re-clone frequently you may need to buy a data pack
(Settings → Billing → Git LFS).

## 5. Safe-to-delete checklist

Before deleting the local `D:\Amazon Proj Approach 3\amazon-hackathon` folder, confirm:

- [ ] `git status` is clean and the `Approach-3` branch is pushed (see §1).
- [ ] The LFS objects are uploaded — after a push, `git lfs ls-files` lists them and the
      GitHub web UI shows the real file sizes.
- [ ] The challenge dataset is available elsewhere (official download or the private
      `amz-er-2026-raw` Kaggle dataset), since it is not in git.
- [ ] `kaggle.json` / API tokens are stored somewhere safe (never in git).
- [ ] Any results you need beyond `output/` + `submission/team_submission.zip` are either in
      git or regenerable.
